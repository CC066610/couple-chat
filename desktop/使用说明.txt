两个人的聊天 · CoupleChat 1.5
============================

一个只属于两个人的聊天：没有服务器、没有账号、没有云端。
两个人各自打开这个程序，用一串二维码（或一串文字码）握手，浏览器之间直连，
聊天记录只保存在各自电脑的浏览器里。可以发文字、图片、视频、文件、语音消息。

怎么开始（两步）
----------------
1. 双击 CoupleChat.exe。会弹出一个黑窗口（别关它），并自动打开浏览器。
   窗口里会打印两个地址：
     本机打开             http://127.0.0.1:8123/
     让对方在局域网打开   http://192.168.x.x:8123/
2. 把「让对方在局域网打开」那个地址发给对方（对方要和你在同一个 Wi-Fi / 同一网段）。
   他也在自己的电脑上双击同一个 exe，然后互相交换地址里的那串码即可。

配对（三种方式，任选）
----------------------
· 摄像头扫码：一端点「生成邀请二维码」，另一端点「扫描二维码」对着屏幕扫。
· 粘贴（推荐跨设备用）：把页面上显示的那串码复制给对方，对方粘进「粘贴对方的码」框，点「处理这个码」。
· 同机两个窗口：可以用两个不同端口各开一份（见下面的 --port），方便自己先试。

流程是两次往返：A 生成邀请码 → B 接受后生成回复码 → A 接受回复码 → 直连建立，双方显示「已绑定」。

手机 / 另一台电脑通过局域网 http:// 打开时，浏览器不允许调用摄像头（只有 localhost 和 https
才放开）。这种情况请用「粘贴对方的码」。语音消息的麦克风同理：在 http:// 的局域网页面上，
浏览器可能不给麦克风权限，此时请用本机 localhost 打开，或直接在手机 App 里录。

发图片 / 视频 / 文件（1.2 起）
-----------------------------
· 点输入框左边的「＋」选文件；也可以直接把文件拖进聊天区，或截图后 Ctrl+V 粘贴。
· 单文件上限 300 MB；图片和视频会内嵌预览，其它类型显示成可下载的条目。
· 传输是分块加密的（32 KB 一块，每块独立 IV，AES-256-GCM），带背压控制，不会把内存和链路打满。
· 附件在落库前就已加密：本机存的是密文块，明文只在显示时临时解密。

发语音消息（1.3 起）
--------------------
· 点输入框左边的 🎤 开始录，再点一次停止并发送；录的时候可以点「取消」丢掉。
· 太短（<0.4 秒）或空的录音会提示「太短了」，不会发出去。
· 收方看到的是可播放的音频条，名字后面带时长，例如「语音 20-12-28.webm（0:03）」。
· 录音格式优先 opus/webm，Safari 那边会退回 mp4/m4a。

绑定规则
--------
· 同一时间只能绑一个人。已绑定时点「生成邀请二维码」会被拒绝：已经和一个人绑定，解除后才能与别人配对。
· 解除是单方的：任何一方点「解除关系」→ 再点「确认解除」就立即生效，不需要对方同意。
  对方那台机器如果在运行，会立刻收到通知并清空这段关系与本机历史；如果当时不在线，他下次打开时已无对端记录，只能重新扫码配对。
· 解除后本机消息记录与附件都会被删除（两边都删）。

隐私与边界（说清楚）
--------------------
· 没有任何服务器：没有账号、没有云端备份、没有第三方能看到聊天内容。
· 消息与附件在写入浏览器数据库之前就已用会话密钥（ECDH → HKDF → AES-256-GCM）加密。
· 链路是浏览器之间直连（WebRTC），二维码里装的就是握手信息（压缩到 ~700 字符）。
· 身份用指纹核对：页面上显示的「对端指纹」可以当面对一遍，防止被中间人替换。
· 清空浏览器数据 = 身份和历史一起消失，这就是「只存在你设备里」的另一面。别用无痕窗口。
· 对方不在线时消息发不出去（点对点直连的必然结果）。
· 防不住对方截图，也防不住刻意改造过的客户端。
· 没有内置 STUN/TURN：同一局域网最稳；要跨公网 NAT 需要自己加 STUN，那就有服务器了，属于另一种取舍。

已读回执 / 通知 / 免打扰
-------------------------
在「说明 → 偏好」里，三个开关各自设置：
  · 已读回执：需要双方都开启才生效。开启后，最新一条消息下面会显示「已读」或「已送达」；
    新消息发出后旧消息上的「已读」会自动消失。任一方关掉即立刻失效。
    "已读"的含义是：对方页面当时是可见状态、并且已经读到。切到别的窗口不算看到。
  · 桌面通知：页面在后台时提醒新消息；第一次勾选时浏览器会询问通知权限。
  · 免打扰：只压通知，消息照收；这是你自己的开关，对方关不掉，也不能替你开。

命令行参数
----------
CoupleChat.exe [--port 8123] [--no-open] [--help]
  --port N     指定端口（默认 8123；被占用会自动往后找，窗口里会打印实际端口）
  --no-open    不自动打开浏览器
  --help       显示帮助

切后台保持直连（v1.7）
-------------------
· 电脑端：浏览器标签在后台时，直连通常还在；但电脑睡眠/合盖会断。
· 手机端：v1.7 起用「前台服务 + 常驻通知」守着进程，切后台/短暂息屏不再立刻断。
  代价是一条通知；想结束就划掉那个通知或用系统设置停掉。
· 断链时不再丢消息：发出去失败的消息会进"待发"，重连成功后自动补发。
· 回到前台若发现链路已断，会自动把重连邀请准备好，你只要让对方贴一次码。

长时间后台保活（v1.8）
---------------------
· 手机端在「说明 → 后台保活」里能一键「允许后台运行（电池白名单）」，点了以后深睡也不会被掐。
· 保活服务不再有 1 小时限制，唤醒锁常驻并每 20 分钟自动续；从最近任务划掉也不会立刻断。
· Android 15 起 dataSync 前台服务有约 6 小时/24 小时 的系统上限，到点系统会收走——那时会退回"断线→重连"。

常见误用：不要拿 22 个字符的身份指纹当配对码（v1.5 已加提示）。

发送图片 / 视频 / 文件（v1.6）
-------------------------
· 聊天框左边「＋」：选相册里的图片/视频，或任意文件（可多选）。
· 也可以直接 Ctrl+V 粘贴图片，或把文件拖进聊天区。
· 手机端「＋」会打开系统选择器（相册/文件管理）；选完会显示进度，收方收到后图片直接显示、视频点开播放。
· 单个文件上限 300 MB。

语音消息（v1.3）
------------
· 点左下角麦克风开始录，再点一次（或点勾）发送；录音里可以随时取消。
· 手机端首次录音会申请麦克风权限，拒绝就录不了。

连接断了怎么办（v1.6 起提示更明确）
--------------------------
· 换 Wi-Fi / 切 4G / 手机息屏太久 / 对方关了页面，直连都会断——这是点对点直连的固有代价，
  没有服务器就没有"重新连上"的中间人。
· 恢复方式：点「重新连接」生成新邀请码，让对方用「粘贴对方的码」接上（身份和历史都还在）。

常见误用：不要拿 22 个字符的身份指纹当配对码
--------------------------------------------
页面上「你的设备」里那串 22 个字符是身份指纹（公钥的哈希），作用是让对方核对"是不是同一个人"。
建立连接必须用配对码：那是 700 多字符的长串（含握手信息、公钥与签名），由「生成邀请二维码」产生。
把指纹贴进「粘贴对方的码」会被明确拒绝——它没有任何可用来寻址或握手的字段。

想在同一台电脑上自测：开两个窗口分别跑
  CoupleChat.exe --port 8123
  CoupleChat.exe --port 8124
两个不同端口 = 两个独立站点 = 两套独立的身份与历史，于是可以自己跟自己配对。

自测小工具：在地址后面加 #dev
-----------------------------
本地排查用，正式使用不需要。加了 #dev 之后页面上会多一行按钮：
「发一张生成的图」「发 1.2 MB 测试文件」「发一段合成语音」「取对方 offer 码」「取对方 answer 码」。
前三个在任何模式下都能用（自己就能验通链路和附件）。
最后两个「取码」按钮要靠开发用的 node 服务（couple-chat/serve.mjs）交换握手码，
打包好的 exe 里没有那个接口，所以点了会失败——这不影响正常使用，正常配对用扫码或粘贴码。

卸载
----
删除 exe 即可，不留注册表、不装服务、不写系统目录。
浏览器的聊天记录如果要清掉：在页面里点「解除关系」，或清空该站点的浏览器数据。

校验
----
SHA256.txt 里有本 exe 的哈希。命令行核对：
  certutil -hashfile CoupleChat.exe SHA256

源码
----
前端与文档在 couple-chat/（app/、test/、docs/）；
这个 exe 由 desktop/build.py 用系统自带 csc.exe 把 app/ 里的资源打包编译而成，可自行复现：
  python desktop/build.py --version 1.3
